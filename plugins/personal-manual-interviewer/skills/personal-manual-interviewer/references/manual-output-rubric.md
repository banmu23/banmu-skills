# Manual Output Rubric

Use this reference when writing the final `个人说明书`.

## Overall Standard

The manual should be:

- Complete enough for an Agent to understand the person and help them next time.
- Clear enough for the user to read without professional background.
- Honest about what is confirmed, inferred, missing, or private.
- Useful for content, product, sales, delivery, and Agent collaboration.

Do not split into multiple files unless the user asks.

## Default Structure

```markdown
# 个人说明书

## 这份说明书怎么用
## 我是谁
## 我的经历和优势
## 我主要帮谁
## 客户最常卡在哪里
## 我能帮他们解决什么问题
## 我现在卖什么 / 提供什么服务
## 客户一般怎么找到我
## 客户为什么愿意相信我
## 客户通常怎么决定下单
## 我怎么交付
## 我平时怎么说话
## 我喜欢的表达
## 我不喜欢的表达
## 可以公开说的案例
## 只能自己和 Agent 参考的信息
## 不能乱说的信息
## 我希望 Agent 怎么协助我
## 我现在最想推进的事
## 接下来要补充什么
## 更新规则
```

If a section has little information, keep it and write `待补充`. Do not delete important sections just because the user answered lightly.

## Section Guidance

### 这份说明书怎么用

Explain that this document helps future Agents understand the user quickly and avoid repeatedly asking background questions.

### 我是谁

Write a concise introduction in first person or close third person, depending on the user's style.

Include:

- Name, nickname, or public identity if provided.
- Current role.
- Field or focus.
- One-sentence positioning.

### 我的经历和优势

Include real background, strengths, experience, and turning points.

Do not exaggerate. If years, numbers, credentials, or results are unclear, mark `待确认`.

### 我主要帮谁

Describe the most likely customers in plain words.

Use labels like:

```text
独立老师
知识 IP
咨询师
教练
自媒体创作者
一人公司
小团队负责人
```

Only include labels supported by the user's answers.

### 客户最常卡在哪里

Write customer pain in scenes, not abstract theory.

Good:

```text
他们不是没有想法，而是素材很多，却不知道先整理哪一块。
```

Avoid:

```text
目标用户存在内容资产沉淀和转化链路缺失问题。
```

### 我能帮他们解决什么问题

Translate service value into customer outcomes:

- Save time.
- Make things clearer.
- Start easier.
- Sell more naturally.
- Deliver more steadily.
- Turn experience into reusable material.

### 我现在卖什么 / 提供什么服务

List current and planned offers.

For each offer, include only confirmed:

- Name.
- Who it is for.
- What problem it solves.
- How it is delivered.
- Price or rights only if confirmed.

If not confirmed, write `价格待确认`, `权益待确认`, or `交付方式待补充`.

### 客户一般怎么找到我

Include content channels, private community, referrals, live events, courses, search, offline activity, or other paths if provided.

### 客户为什么愿意相信我

Use real proof only:

- Experience.
- Past work.
- Customer feedback.
- Case stories.
- Results.
- Published content.
- Long-term relationship.

Separate `已确认` from `待补充`.

### 客户通常怎么决定下单

Write the decision path in simple words:

```text
先看到内容
开始觉得这个人懂我
再看到案例或服务说明
最后来咨询 / 报名 / 下单
```

Only describe what is supported by the user.

### 我怎么交付

Describe how the user helps after purchase:

- One-on-one.
- Course.
- Community.
- Document.
- Review.
- Live session.
- Ongoing support.
- Custom project.

Keep boundaries clear.

### 我平时怎么说话

Use plain wording:

```text
我说话偏直接
我喜欢讲真实例子
我不喜欢太夸张
我希望语气像聊天
```

Do not give this section a stiff or technical title.

### 我喜欢的表达 / 我不喜欢的表达

Use examples when possible.

Include:

- Words the user likes.
- Words to avoid.
- Tone preferences.
- Punctuation or style habits if mentioned.

### 可以公开说的案例

Include only examples the user clearly allows or that are already public.

If unclear, write:

```text
以下案例暂时只作为内部参考，公开前需要确认。
```

### 只能自己和 Agent 参考的信息

Put private details here:

- Private names.
- Private screenshots.
- Internal prices.
- Unpublished plans.
- Customer chats.
- Sensitive results.

### 不能乱说的信息

Always include:

```text
不要编造收入、销量、客户结果、价格、名额、权益、日期、承诺和客户反馈。
不确定的信息必须标注待确认。
```

### 我希望 Agent 怎么协助我

Write practical use cases:

- Draft content.
- Organize materials.
- Polish product descriptions.
- Extract customer questions.
- Build simple workflows.
- Prepare documents.
- Summarize meetings.
- Help clarify offers.

### 我现在最想推进的事

List current priorities if provided.

### 接下来要补充什么

Use a short checklist.

Ask for only the most useful next 3-5 missing pieces.

### 更新规则

Explain:

```text
如果我以后给出最终版介绍、产品更新、客户反馈、公开案例或新的表达偏好，Agent 应该把稳定信息补进这份说明书。
```

## Language Rules

Use simple section headings and natural sentences.

Avoid customer-facing jargon and labels that sound like a formal report.

If a professional idea is necessary, translate it:

```text
商业定位 -> 我是谁、我帮谁、我靠什么赚钱
客户画像 -> 我主要帮谁
转化路径 -> 客户怎么从认识我到下单
交付 SOP -> 我怎么帮客户完成这件事
表达风格 -> 我平时怎么说话
风险边界 -> 哪些话不能乱说
```

## Final Self-Check

Before final output, check:

- Does the manual clearly say who the user helps and how they make money?
- Does it avoid forcing the customer to understand professional terms?
- Are uncertain prices, rights, results, cases, and feedback marked?
- Does it include how Agents should help next time?
- Does it include what not to invent or expose?
- Does it feel like a useful personal manual, not a questionnaire summary?
