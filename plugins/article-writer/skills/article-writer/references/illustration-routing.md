# 配图路由与内置小黑配图 Skill

## 定位

本文件是「文章一键成稿」内置的客户安全版小黑配图 Skill。它保留「专属人物配图版」的正文配图方法论，但不包含他人的私人照片、专属脸型锚点或他人专属服装设定。

仅当客户没有自己的小黑配图 / 个人 IP 正文配图 Skill 时启用。客户已有类似 Skill 时，自动优先调用客户自己的版本。

## 配图总优先级

严格按以下顺序执行：

1. 客户预先上传、置顶、精选、指定必用的图片。
2. 原文章、原飞书文档、知识库或附件中的可用原图。
3. 真实结果、真实界面、真实过程、真实产品和真实案例截图。
4. 客户已有的小黑配图 / 个人 IP 正文配图 Skill 生成的解释型插图。
5. 本文件内置的小黑配图 Skill 生成的解释型插图。

不得用 AI 生图替换真实证据，不得把 AI 生成界面冒充真实截图，不得为了画面统一而遗漏客户置顶或指定必用图。

## 原图与小黑配图双轨强制执行

“原图优先”只定义证据优先级和落位顺序，不代表原图与小黑配图二选一。

- 客户原图、截图、海报和照片负责证明真实发生过什么。
- 小黑配图 / 个人 IP 正文配图负责解释关键判断、流程关系、前后对比、易卡点、业务闭环和全文收束。
- 客户提供了可用附图时，先完整保留并插入原图，再自动调用最匹配的客户专属小黑配图 Skill；没有专属 Skill 时，进入本文件的内置兜底流程。
- 不得因为“文章已经有图”“真实截图很多”“客户给了海报”而把小黑配图数量降为 0。
- 只有客户明确说“不要生成小黑配图”时才能跳过，并在交付检查中记录这一明确选择。缺少角色基准图、授权或生图能力时，要启动校准或兜底流程并说明阻塞，不能静默跳过。

最终 QA 必须分别统计：可用原图总数、实际插入原图数、小黑配图总数及每张小黑图的正文锚点。客户提供了可用原图且未明确拒绝小黑配图时，两类实际插入数量都必须大于 0，否则不得判定文章或飞书文档已完成。

## 自动发现客户配图 Skill

检查以下位置：

- 当前可用 Skills 列表。
- 客户上传的 Skill ZIP、`SKILL.md` 或项目说明。
- 客户知识库中的个人 IP、文章配图、视觉形象或小黑配图目录。
- 当前会话已确认的配图 Skill 和角色基准图。

不要只按名称匹配。满足以下能力即可视为类似 Skill：

- 能为正文生成解释型插图。
- 有客户自己的角色照片、角色板或身份锚点。
- 能根据文章段落设计 shot list 和插入位置。
- 正式图使用可靠的位图生图能力，且具备角色一致性和 QA 规则。

若有多个候选，依次优先：客户本人专属身份锚点最完整、最近更新、已通过真实文章测试、QA 更严格的 Skill。匹配清楚时直接调用，不让客户重复选择。

内部任务可以调用 `customer-specific-illustration-skill`。客户任务不得因为当前环境安装了他人专属版本，就把他人的脸、照片或服装当成客户形象。

## 没有客户专属 Skill 时的主动引导

先检查客户是否已经上传或置顶了个人照片、品牌照、角色板或历史配图。已有资料就直接复用，不重复索要。

如果确实没有，主动、耐心地告诉客户：为了让文章中的小黑主角真正像客户本人，需要先完成一次个人 IP 形象校准。优先索取：

```text
最低可用：1 张清晰正脸照 + 1 张能看清身形和常用穿搭的半身或全身照
理想组合：正脸、三分之二侧脸、侧脸、全身、常用穿搭、2-4 张典型表情或动作
```

同时只补问无法从照片和知识库判断的必要变量：

```text
个人 IP 名称
固定发型、眼镜、胡须或其他识别点
固定上衣、下装、鞋子和标志物
希望呈现的性格与常见动作
绝对不能出现的服装、年龄、气质、关系和视觉禁忌
```

说明隐私边界：照片仅用于当前客户的私人 IP 校准，不进入通用 Skill 包，不与其他客户共用，不公开发布原始照片。

如果客户暂时不提供照片，不要偷偷使用他人形象，也不要假装通用人物就是客户本人。可以先完成文章、原图排布和无人物解释图 shot list，把人物型配图标记为“等待客户形象确认”。

## 客户 IP 一次性定稿流程

1. 从照片提炼脸型、发型、年龄感、身形、服装、标志物、性格和禁忌。
2. 输出简洁的客户角色设定，请客户确认明显错误。
3. 使用 `image_gen` 生成第一版主形象和角色基准图，不使用 SVG、HTML、Canvas、PPT、流程图或贴图拼接。
4. 逐项检查相似度、脸色、发型、服装、身形、手脚和标志物；根据客户反馈耐心迭代。
5. 客户明确确认后，再生成三视图、表情动作图和 2-3 张正文配图基准图。
6. 将确认后的角色设定、参考图和基准图保存到客户自己的私有项目或知识库位置。
7. 后续文章直接复用已确认资产，不再每次从零询问。

未经客户确认，不把试验图当成正式文章配图。

## 内置小黑正文配图方法

先读完整文章，找出需要图解的认知锚点：核心判断、前后对比、关键动作、易卡点、输入输出、业务闭环、方法层级和最终收束。不要平均分配，不设固定张数。

每张图只解释一个核心意思，并写清：

```text
插入位置
正文判断
主角动作
核心物件或隐喻
建议短标注
该图和已有原图的分工
```

正式正文图必须逐张使用 `image_gen` 生成 PNG。默认视觉 DNA：

- 16:9 横版正文配图。
- 纯白背景、黑色简洁手绘线稿、大量留白。
- 少量红色、橙色、蓝色中文手写批注。
- 客户本人是核心动作主角，形象以客户已确认的角色基准图为准。
- 怪诞、有趣、清爽，但不幼稚、不油腻、不像商业矢量海报。
- 不生成真实产品 Logo、伪造界面、伪造付款、伪造客户反馈或伪造结果证据。
- 禁止把 SVG、HTML、Canvas、流程图、PPT 图、截图拼贴或贴图拼接当成正式正文图。

## 生图硬性 QA

每张图交付前逐项检查：

- 主角是否像客户已确认的个人 IP，而不是他人或泛化陌生人。
- 发型、服装、标志物和年龄感是否一致。
- 每个人物严格只有两条手臂和两只手；手必须沿手腕、前臂连接到正确肩膀。
- 不得出现多手、多臂、悬空手、重复手、融合手、错位手腕、断臂、额外手指或畸形肢体。
- 脸色干净、自然、明亮，不灰黄、不斑驳、不被密集排线污染。
- 一张图只讲一个核心结构，主体不挤满画面，中文标注少而可读。
- 图片不能替代或冒充真实证据。

任一人物出现多手、多臂或错误肢体连接时，整张图直接判废并重生成。

## 与文章排版的合并交付

最终配图清单必须把原图和新图合并排序，并标明来源：

```text
原图 / 置顶必用图
真实证据截图
客户专属 Skill 生成
内置小黑 Skill 生成
```

用于飞书或知识库时，先完成文档结构与排版，再插入小黑配图；插入后检查图片是否仍在正确段落、尺寸是否正常、原图是否完整保留。

飞书交付完成前，必须再核对一次：原图证据链是否完整、小黑解释链是否覆盖关键判断与流程、两类图片是否分别计数、是否存在“因为已有原图而漏掉小黑”的情况。
