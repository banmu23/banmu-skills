# Evidence Chain Rubric

## Purpose

A practical public-account article should not merely “include images”. Each image must prove, explain, or lower the reader's operating threshold.

## Image Source Priority

Before generating anything new, inventory every image the customer has already uploaded, pinned, featured, linked, or embedded in the source document.

Use this order:

1. Customer-pinned or explicitly required original images.
2. Usable original images from uploads, attachments, knowledge base, and source documents.
3. Real proof screenshots and process images.
4. Customer-specific Xiaohei / personal-IP illustrations for explanation gaps.
5. Embedded-fallback Xiaohei illustrations after customer identity confirmation.

Generated illustrations must supplement the evidence chain, never replace real proof or cause a required original image to be omitted.

## Image Roles

Use images in these roles:

```text
Result proof: payment, order, feedback, before/after, finished output
Context proof: source material, original group digest, client question, real task brief
Tool proof: interface screenshot, project directory, editor view, document view
Process proof: Agent output, command result, flow record, generated file list
Teaching proof: where the reader should click, what a finished step looks like
Handoff proof: product/course/service poster or deliverable preview
```

## Placement Rules

1. Put result/proof images near the opening when they build trust.
2. Put tool screenshots before the steps that use the tool.
3. Put process screenshots immediately after the action they prove.
4. Put final output screenshots after the workflow result.
5. If two images prove the same result, place them side by side when the platform supports it.
6. Do not add captions above and below the same image. One clear caption is enough.

## Caption Rules

Captions should answer:

```text
What is this image?
What should the reader notice?
Why does it matter to the workflow?
```

Avoid internal labels such as:

```text
结果前置
证据链截图
图 1：案例证明
```

Those are author notes, not reader-facing writing.

## Evidence Gap Handling

If an important claim has no evidence:

- Ask for a screenshot if the article depends on it.
- Or rewrite the claim as a softer observation.
- Or mark it as a personal judgment.

Never fabricate numbers, payments, feedback, case details, dates, rights, or product claims.
