# 一键生成高质量朋友圈

## 目标

把真实素材、配图和知识库转成一条接近可直接发布的朋友圈。

默认先交付成品，不先讲写作过程。让正文像发布者正在分享一件真实发生的事，而不是文章、课程讲义、销售页或 AI 模板练习。

## 触发边界

出现以下意图时优先使用本 Skill：

- 写朋友圈、发圈、朋友圈文案、朋友圈直发
- 根据知识库、历史内容或客户资料写朋友圈
- 看图发圈、根据截图或海报配文
- 改写、仿写、润色、压缩、校准朋友圈口吻
- 把案例、反馈、产品更新、工具测试、活动或个人状态转成朋友圈

如果用户只是在整理截图、归档素材、讨论平台规则或维护目录，没有生成或改写文案的目标，不要触发本 Skill。

## Quality First Token Efficiency（质量优先与 Token 节省）

按以下优先级执行：

1. 成品质量、事实准确、隐私安全、证据判断和业务判断。
2. 减少无效读取、重复追问和过程解释。

不要为了省 token 跳过必要的事实核验、图片判断、风格校准或风险检查。

先判断任务目标和最小必要资料源。长资料、群聊、PDF、历史内容和图片证据链要分批提炼、先建索引、按需深入。复用已确认的风格文件、产品资料、终稿和复盘，不要每次从零读取整库。

## Workbench Sync Loop（工作台同步闭环）

当使用方提供最终发布版、改稿意见、发布复盘、产品资料变化、案例反馈或真实使用反馈时，先判断它是一次性偏好还是稳定规则。

稳定且可复用的规则，应同步评估是否更新 `SKILL.md`、`references/`、使用说明、客户知识库模板、跨平台调用提示词、产品服务卡和一键上传 ZIP。涉及价格、权益、公开承诺、客户隐私、未确认数据或新命名时，只列为待确认项，不擅自写入客户可见包。

## 资料优先级

按以下顺序取材，越靠前优先级越高：

1. 用户本轮提供的事实、图片、限制和发布目标。
2. 发布者亲自确认的最终发布版。
3. AI 初稿与发布者终稿的对照、改稿意见和发布复盘。
4. 近期历史朋友圈和稳定风格说明。
5. 产品、服务、受众、案例、反馈和风险资料。
6. 通用模板与方法论。

最终发布版高于模板。最新确认信息高于旧资料。动态事实冲突时，标记 `【需确认最新版本】`，不要自行拼接。

## 必要上下文

尽量从资料中识别以下信息，只追问真正缺失且会影响事实或发布安全的变量：

- 谁在发：个人、客户、品牌或团队。
- 发什么：真实事件、结果、状态、判断或行动。
- 为什么发：记录、建立信任、获客、转化、招募、发布、预热或复盘。
- 给谁看：外部读者是否理解人物、背景、产品和内部称呼。
- 证据是什么：截图、数据、反馈、界面、过程记录、交付结果或实物。
- 图片各自承担什么：主结果、证据、反馈、权益、过程或补充。
- 哪些不能写：隐私、未确认数据、动态价格、权益、日期、名额或承诺。

素材不足时，先写最稳妥的可用版本，并只对关键缺口标记 `【需补充】` 或 `【需确认】`。

## 工作流

### 1. 建立事实与证据卡

在内部快速整理：

```text
发布者：
目标读者：
真实事件：
人物与关系：
可确认结果：
对应证据：
产品 / 服务关联：
核心业务价值：
动态信息：
隐私与风险：
缺失事实：
```

不要机械照搬聊天昵称。根据素材把人物归一为自然、可公开的称呼；原昵称只作为内部证据。

### 2. 判断内容类型

优先识别以下类型：

- 结果 / 成绩
- 客户或成员案例
- 好评 / 反馈
- 产品 / 服务
- 产品上线 / 内测招募
- 工具 / Agent / Skill / 工作流
- 课程 / 直播 / 活动通知
- 个人状态 / 生活现场
- 复盘 / 认知判断

一份素材可以同时有多个资产身份。成员反馈可能同时证明人物案例、产品权益、交付待遇、共创关系和业务价值，不要压扁成普通好评。

### 3. 提取本人的表达指纹

资料足够时读取 `references/style-extraction.md`，提取：

- 开头方式
- 常用长度和内容块数量
- 句子长短与换行气口
- emoji、微信表情和分割线习惯
- 判断句、口语、幽默和禁用表达
- 产品称呼和业务价值语言
- CTA 轻重
- 配图承接方式

模板只作检查清单，不按原句套写。不要把单条爆款或单条发售稿误当成全部风格。

### 4. 选择最强开头

优先级：

1. 明确结果、成绩或完成节点。
2. 人物 + 身份关系 + 发生了什么。
3. 当前事件或动作。
4. 有证据支撑的反差、痛点或判断。

没有结果时，第一句直接交代主要事件。不要从“AI 时代”“今天想分享”“很多人问我”这类空泛铺垫开始，除非历史终稿明确支持且本次事件需要。

### 5. 写一版可直发正文

遵守这些写法：

- 一条朋友圈优先讲透一件事。
- 结果、事实和现场先于方法论。
- 正文要让不在群里、不认识人物的外部读者也看得懂。
- 真实证据后只提炼最关键的判断，不逐字复述截图。
- 技术词先翻译成读者能完成的任务，再说明 Agent、Skill、API 或工作流。
- 工具价值要落到真实流程，如内容、资料、客户消息、交付、获客、转化或经营。
- 需要转化时，让产品自然承接事实和价值；证据弱时不要硬推。
- 口语、幽默和网络表达必须服务理解，不能为了“像本人”硬加口头禅。

短句不等于碎片化。按语义气口组织：

```text
句内换行：同一个意思中的呼吸
段间空行：进入下一层意思
分割线：案例、方法、产品或 CTA 等大板块切换
```

总结上一句的锤定音要贴着上一句，不要漂成 PPT 标题。

### 6. 让正文与配图发生关系

有配图时先排序角色：

```text
主图：第一眼结果或产品
证据图：支撑数据、反馈或判断
权益图：支撑产品、价格或交付信息
过程图：支撑真实现场
补充图：提供背景
```

正文不必解说每张图，但必须知道哪张图证明哪句话。必要时用 `附图1`、`主图`、`反馈图` 等精确指向。提醒打码姓名、头像、群名、联系方式、订单、金额、地址和其他敏感信息。

### 7. 按类型校准结构

需要类型骨架时读取 `references/content-patterns.md`。特别检查：

- 案例型：结果、人物关系、方法判断、证据、产品承接、个案边界。
- 工具型：人话解释、自然语言动作、真实业务流、照做步骤、踩坑、动态风险。
- 产品上线型：能否使用、行动入口、功能压缩、差异化关键、开发证据、共创角色、参与下一轮。
- 通知型：时间、对象、具体任务、参与路径、已有用户分流和动态权益。
- 反馈型：不能只写“被夸了”，要识别它证明的产品和交付价值。

### 8. 运行发布前检查

使用 `references/direct-post-rubric.md` 检查并自行修改。重点确认：

- 第一屏是否出现最强事实。
- 外部读者是否看得懂。
- 事实、因果和承诺是否有证据。
- 是否像真实的人在发，而不是 AI 总结。
- 短句是否有气口而非碎片化。
- 配图是否真正承接正文。
- CTA 是否与证据强度相称。
- 价格、权益、名额、日期、平台能力和结果是否需确认最新版本。
- 是否完成隐私检查。

## 默认输出

先给用户可复用成品：

```text
朋友圈正文

<一版可直接发布的正文>

配图建议
<仅在有图或需要配图时输出>

发前检查
<仅列需确认的事实、动态信息、打码或风险事项；没有则写“无”>
```

用户只要正文时，不额外附写作分析。用户要求多个版本时，只给真正不同的版本，例如更短、更锋利、更克制，不要做同义改写堆叠。

## 硬规则

- 不编造案例、反馈、收入、销量、成交、数据、价格、权益、名额、日期、合作关系或产品能力。
- 不把个案写成普遍结果承诺，不把相关性写成确定因果。
- 不把“不登录账号”“隔离使用”“测试正常”等事实升级为“完全零风险”。
- 平台状态、入口、支持工具、积分、模型、支付、价格、权益和活动时间均按动态信息处理。
- 客户、学员、付款、私聊、截图、交付资料默认私密。
- 不自动发布朋友圈，只生成、检查和迭代文案。
- 不机械模仿私人生活、敏感身份、医疗、金融或其他高风险表述。
- 不因为用户要求“更有冲击力”而突破事实和隐私边界。

## 迭代与终稿回流

用户说“再短一点”时，重新抓真实事件、核心判断和自然 CTA，不要只删句子。

用户说“更像我”时，对照表达指纹调整开头、气口、换行、口语、emoji、判断词和 CTA，不要只加入网络词。

用户给出最终版、已发版或亲自润色版时：

1. 把最终发布版视为最高优先级样本。
2. 对比初稿与终稿的信息顺序、承接、句式、表情、配图和 CTA。
3. 区分一次性表达与稳定规则。
4. 在当前项目允许时，把稳定规则回写到风格、方法论、产品资料或本 Skill 的维护源。

如果用户零修改发布，也要反推命中的原因，不能跳过学习。

## 辅助脚本

本地知识库包含大量 `.md`、`.txt` 或 `.csv` 朋友圈时，可用只读脚本提取粗粒度风格统计：

```bash
python scripts/profile_corpus.py <folder-or-file>
python scripts/profile_corpus.py <folder-or-file> --split-mode heading --json
python scripts/profile_corpus.py <posts.csv> --column content
```

统计结果只是辅助证据，不能替代对最终发布版的人工语义判断。

跨平台部署时读取 `references/portable-agent-prompt.md`。
