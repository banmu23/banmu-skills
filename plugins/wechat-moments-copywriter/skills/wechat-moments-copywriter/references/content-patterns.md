# 朋友圈内容类型骨架

这些骨架用于选信息和检查遗漏，不用于逐句套写。先从真实素材中找最强事实，再决定是否需要其中某个结构。

## 结果 / 成员案例

适用：新账号冷启动、内容结果、产品结果、学员或成员阶段成绩。

```text
时间压缩 + 明确结果
人物身份与关系
这件事真正说明什么
证据由哪张图承担
最直接相关的产品或服务
必要时再承接更高阶业务价值
个案与动态信息边界
```

不要把成员案例写成普通夸夸。也不要把个人能力、平台推荐、工具、执行节奏和产品场域写成单一确定因果。

## 好评 / 反馈

```text
最有信息量的原话或事件
反馈者与发布者 / 产品的关系
它证明了哪项交付、权益、共创或支持
这对目标读者意味着什么
自然承接下一步
```

“被认可了”不是核心。核心是这条反馈证明了什么真实能力或业务价值。

## 新工具 / Agent / Skill / 工作流

```text
一个明确的趋势或业务判断
工具用人话登场
它不是什么，真正是什么入口
读者可以直接说出的自然语言动作
它能进入的真实业务流
本人刚跑过的照做路径
真实踩坑与边界
为什么表层功能之外值得兴奋
```

不要写成功能列表或安装手册。涉及平台入口、授权、兼容性和安全时按动态信息处理。

## 公域趋势 / 工具与 Skill 权益承接

适用：平台出现新的工具 / Skill 分发入口，已有真实公开案例，同时有现成产品能力可以帮助读者下场。

```text
可核验的公开案例与硬数据
平台最近发生的变化
过去与现在的用户行为差异
官方事实与近期案例观察分开
一句明确的当下判断
选工具、录演示、发公域、能挂则挂的行动路径
只承接最相关的一两项现成权益
用一个具体工具示范怎样照做
内容被看见 -> 工具被使用 -> 业务被认识
轻量行动时机提醒
```

不要把单个案例写成普遍结果，不把平台扶持写成必然推流，也不要混淆不同平台的官方能力。平台入口、开放范围、活动规则、挂载权限和权益数量按动态信息处理。

产品承接要通过【怎么用】出现，不要突然堆完整权益清单。客户可见版本使用通用产品关系和通用示例，不写入维护者自己的产品名、成员名或内部群聊信息。

## 产品正式上线 / 内测招募

```text
多久做完 + 和谁做 + 产品现在能用
官网或体验入口
评论口令 / 内测反馈群 / 参与方式
X 个功能，1 个差异化关键
界面、结果页和真实输出证据
开发周期、提交或模块等真实硬证据
人物与 AI 的共创分工
产品证明的能力和下一轮共创
```

生活化隐喻可以统一使用，但不要一段换一个梗。开发数字必须有记录。不要把单次开发速度写成普遍承诺。

## 课程 / 直播 / 活动通知

```text
时间节点或当前现场
活动是什么、谁适合
帮助完成的具体任务或结果
最关键内容或大纲
如何参与
已有用户与新用户如何分流
价格、权益和截止时间确认
```

当成品海报已经清楚承载标题、时间、人物、内容看点和真实参与入口，且活动临近或当天发生时，正文可以压成 2-3 个信息块：

```text
产品 / 活动发布钩子
预约动作 + 时间 + 人物 + 活动形式 + 一个核心价值
好奇句或现场会合 CTA
```

不要复述海报中的完整大纲和方法论。临近开播可以适度增强 CTA，emoji 只承担发布、直播、时间等信息导航。只有海报已经放入并实测真实二维码时，才能写“扫码预约”。

通知不能只报时间地点，也不能把整份课程详情塞进朋友圈。

## 产品 / 服务承接

```text
客户正在经历的具体麻烦
当前素材中的真实证明
产品具体帮助完成什么
适合谁、边界是什么
轻量行动入口
```

先让产品接住真实问题，再给 CTA。证据不足时降低转化强度。

## 个人状态 / 生活现场

```text
一个具体画面或动作
真实情绪或反应
轻微反差、自嘲或关系感
一句不过度拔高的判断
```

生活内容不必强行承接产品，也不要每次都上升到宏大趋势。
