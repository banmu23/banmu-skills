# 跨平台使用与资料结构

本包要求图片读取、带参考图的定向编辑与成品保存能力。Agent先检查现场可用工具；不能仅因平台能上传ZIP就声称已支持图片编辑。未具备图像编辑能力时可以整理事实卡和生产提示，但必须说明图片尚未生成。

通用调用提示：

```text
请使用欢迎海报Skill。先读取SKILL.md和我的私有品牌配置，按已确认母版替换这次成员的信息。
我会提供昵称、四位编号、原始简介和头像。你负责按空间提炼身份、经历及有依据的成长方向/同行期待，选择合适的已确认版式、真实生成并对照验收。不要把每个人都压成同样两行，也不要为填满而编造。
不要编造信息、继承旧成员资料、缩小字号硬塞内容，或把上次成品当新母版。
```

建议私有资料结构（由Agent维护，用户不必手写JSON）：

```text
品牌资料/
  profile.json
  masters/（只保留已确认、清晰的原图）
成员任务/
  本次任务/
    原始简介与头像
    member.json
    job.json + prompt.txt
    候选图与QA记录
    最终海报.png
```

名称与目录沿用用户已有工作流，新增关键目录先遵循用户自己的命名规则。模板示例是虚构输入结构，不是可直接发布的真实成员。客户私有profile、头像、编号、任务记录和原图不进入公开GitHub或共享包。

公开安装包根目录直接含 `SKILL.md`；只安装能力，不自动下载作者私有素材。已有客户配置升级前先显示变化并获确认，保留快照。没有授权素材时不从网络寻找相似真人头像替代。
