# 输入契约与提示词编译

本脚本只验证资料、检查文件和哈希、选择母版并编译任务。它不调用生成工具、不编辑图片、不判定生成海报通过，也不外发资料。标准库运行，无需额外安装依赖。

## 命令与私有文件

```bash
python3 scripts/prepare_job.py --member /path/to/private/member.json --output /path/to/private/new-job
python3 scripts/prepare_job.py --profile /path/to/private/profile.json --member /path/to/private/member.json --output /path/to/private/new-job
```

未指定 `--profile` 时使用 Skill 根目录的 `assets/private-profile.json`。输出为新的私有任务目录中的 `job.json` 与 `prompt.txt`；任一同名文件存在即拒绝覆盖。程序实际回读两文件后才返回 `ready`。这表示节点 06 完成，不表示图片已经生成。

示例 JSON 仅演示契约，使用虚构身份、占位路径和全零哈希。不能直接用于生产。授权母版、头像、实际私有配置、成员 JSON 和生成记录都不应进入公开安装包。

## 成员 member.json

| 字段 | 类型与约束 |
|---|---|
| schema_version | 可省略；提供时为整数 1 |
| nickname | 非空字符串；脚本仅去除末尾重复的“同学”，再附加一次；不截断真实昵称 |
| name_lines | 可选的一行／两行字符串数组；拼接并去除空白后必须与标准昵称完全相同，不允许少字、改字或重复“同学” |
| token | 必须是四个 ASCII 数字组成的字符串，例如 `"0423"`、`"0007"`；整数、三位数、字母 O 均不合法 |
| avatar_path | 存在且可读的 PNG/JPEG/GIF/WebP；相对路径相对于 member.json 所在目录解析 |
| source_text | 本次成员原始简介，非空字符串；不拼接旧母版个人资料 |
| roles | 1–3 个对象；每个对象恰好含 text、evidence，主身份放首行 |
| locations | 0–2 个同结构对象；可省略或使用空数组，表示清除旧地区；正文空间可由有依据的personal_lines复用 |
| personal_lines | 可省略或空数组；0–3 个同结构对象，放有原文依据的成长方向、学习意愿或同行期待，保留愿望状态；不存所在地或新造资历 |
| template_id | 可省略；auto、A、B 之一 |

`text` 是单行上图文字，不能包含换行或不可见控制字符；`evidence` 是 `source_text` 内确实存在的一段原文。脚本核验原文片段存在，但不能凭此保证精简文字与原文语义一致，必须由 Agent 逐行核实。例如“曾参加课程”不能被提炼成“认证专家”。

不允许未知成员字段，避免拼错字段后静默丢失资料。JSON 重复键会被拒绝。

三个正文数组共享同一空间：单行姓名最多5行，A两行姓名最多3行。旧V1事实卡不含 `personal_lines` 时仍可编译。脚本没有最低填充要求；只提供两行且原文确实无补充内容时仍接受，交由Agent调整分组间距并实际看图。不得为兼容旧字段把成长期待伪装成所在地。

## 私有 profile.json

`schema_version` 为整数 1，可选 `default_template` 为 `B`。`visual_contract` 是非空字符串数组，用于描述整体固定视觉约束。`templates` 必须恰好包含 A 和 B，各自有：

| 字段 | 内容 |
|---|---|
| path | 已获授权的原始母版路径；相对于 profile.json 目录解析 |
| sha256 | 64 位 SHA256，必须与当前原图一致；不能自动接受已改变的原图 |
| regions | 对象，必须完整包含 nickname、avatar、roles、locations、token；值为该动态区域的可读边界说明 |
| old_member_terms | 非空字符串数组，列出旧姓名、编号、地区、专属身份等需要逐项核对的内容 |
| fixed_text | 非空字符串数组，逐条给出固定品牌、完整 slogan、价值区、页脚等实际文字 |
| limits | 对象，含 nickname_units、role_units、location_units 三个正整数 |

regions 可以包含参考原图坐标和透视区域描述，但属于提示词约束，并非生成工具的硬蒙版，不能据此承诺区域外像素完全不变。

旧成员信息必须全部落在已定义的动态区域中；不要因脚本只接受五种字段，就把其他位置的旧客户信息误当作固定文字。首次配置由 Agent 查看整图确认字段地图，并实际查看两套原始母版。脚本检查图像格式签名与文件哈希，不等于图像完整解码、身份核对或视觉验收。

## 模板选择与溢出返回

容量是保守估算：汉字／全角字符计 2 单位，ASCII 计 1 单位，组合附加符计 0。昵称容量包含末尾“同学”。这是早期拦截条件，不是字体实际宽度测量；最后仍需检查渲染成品。

- `auto` 默认 B；昵称超出 B 容量时选 A；明确指定两行 name_lines 时 auto 选择 A；两版均不足即返回短昵称确认，不截名、不缩字。
- 显式选 A/B 时尊重选择；姓名超容量则报错，不擅自换版。
- 头像优先时由 Agent 根据用户意图明确指定 A。
- 身份或地区任一行超容量时，返回原文精简；不靠缩小字号或拉扁字通过。
- `personal_lines` 每行沿用该母版 `location_units` 的次级正文容量；不增加profile配置字段，也不放宽原有单行限值。所有正文合计超出5行（两行姓名时3行）返回提炼。
- 示例容量为 A 昵称 22、B 昵称 14，身份 30、地区 24 单位；真实配置应以实际母版和字号验证，不能任意放宽以绕过报错。

A 昵称总长超过 14 单位时，必须拆成两行，每行最多 14 单位。未提供 name_lines 时，仅在空白、中英文边界或昵称与“同学”的语义边界尝试自然拆行，不拆开连续英文词或中文姓名内部；找不到安全断点时返回明确 name_lines 或短昵称。B 姓名始终单行。

两行姓名时，身份最多 2 行、地域最多 1 行，多余内容返回原文精简。保持母版原字号与正常字宽，头像和条码留在原位，在它们之间重新分配动态文字区域；原 regions 坐标只是默认名片的位置提示，不能把两行姓名硬挤进旧单行。私有 profile 的原容量限值不因两行规则而自动放宽。

例如虚构昵称“知夏 Eleanor”可传 `"name_lines": ["知夏", "Eleanor同学"]`；其标准昵称是“知夏 Eleanor同学”，去掉空白后文字必须逐字相同。两行排版仍需真实看图验收，脚本估算通过不代表不会挤压。

## 输出与后续验收

`job.json` 包含原始母版 target 与头像 support 的明确角色、绝对路径和 SHA256；还包含逐字替换清单（含 name_lines）、姓名行数与重排策略、原文依据、固定文字、动态区域、旧成员检查词及生成／验收政策。公开包不应携带实际 job 文件。

`prompt.txt` 明确要求：
1. 每次都从已验证的原始母版开始，头像只作头像素材，禁止将上一位成品或失败图作为下一次编辑目标。
2. 昵称只附加一次“同学”，四位令牌保留前导零，缺少资料时清除旧行。成长和同行期待按原文写入personal_lines，不继承旧地区。
3. 头像保留原主体与照片／绘画／动物／符号类型；不推测或生成人脸。
4. 动态区域之外尽量保持原样；成员正文在头像与条码之间按实际分组调整间距，不得添加数组之外的文字、签名、资料和品牌承诺。
5. 生成式编辑不能保证逐像素一致；输出须按质量规则进行实际目视验收。

旧成员词与新事实确实重合时允许保留；例如新成员也现居相同城市，不应机械删地名。其余旧资料必须消失。脚本不会 OCR 或替你判断图中是否仍有残留。

每件最多三次实际生成；每次失败记录具体原因并回到原始母版，第三次仍失败时报告缺口。任何 `ready` 状态均不可当作已生成、已通过或已交付。
