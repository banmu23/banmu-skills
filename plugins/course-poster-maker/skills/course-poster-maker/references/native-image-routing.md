# 原生能力与可用路线

P04现场发现当前Agent的原生生图或图片插件：先检查实际工具入口、可见字段、参考图／透明支持及限制。有可选择且已验证的更强型号时用它；不暴露型号就记unknown，不把营销名称、GPT/Codex版本或API支持当本账户工具能力。不硬编码未来型号。

|路线|选择依据|必要记录|
|---|---|---|
|native|当前原生工具／图片插件能完成|入口、日期、真实调用和原图|
|native_composite|原生字稿／背景加真实证据、Logo、照片或已存在原生元素的可靠机械组合|客户已授权路线、原生素材溯源、合成记录、冻结检查；无新生图记0|
|hybrid|主视觉原生，中文长文用确定排版|具体失败或阅读需要、路线确认、视觉来源、可编辑排版源|
|html|原生／插件无法稳定清晰生成、平台不具备该能力且客户接受替代|实际限制、路线确认、可编辑HTML及可直接用的长图、真实渲染检查|

优先原生／图片插件。机械组合只是保真制作，不等于代码伪造视觉或证据。客户已要求保留原图、真实截图或只改局部时，任务范围可覆盖必要的机械组合，直接记录依据即可，不因此额外索要一次确认。HTML／hybrid不是静默降级；客户明确已有授权可沿用，缺授权时展示具体方案再确认。不因质量、路径或尺寸控制问题擅自切到付费API、安装第三方服务或索取密钥。

超长图尺寸随内容，先核当前工具能力；原生无法一次容纳时可以提出原生分区＋可靠组合或HTML路线，并核清转场与全局网格。不要宣称任意精确原生尺寸、原生4K、一次必成或平台全部通过。

Codex、Claude Code、WorkBuddy、豆包工作分别记实际入口与实跑状态：未能访问的平台写“流程设计适配、未实测”。Skill的通用流程由Agent阅读执行，不假设平台具备特定子Skill调度／插件。没有当前能力证据时停相应节点并保存已完成内容；客户普通操作保持简单。
