# 当前 Agent 原生生图选路

目标：使用运行当下可用、最新且能力最强的原生图像生成/编辑能力。模型、插件、尺寸与账户权限均可能变化，不能用一份永久模型表替代核验。

## 选路顺序

1. 发现当前 Agent 已提供的原生图像工具/插件，检查实际参数说明与可用权限。
2. 若有多个可选模型，用其当下官方资料核验版本、复杂中文、长图、参考一致性与精细编辑能力；优先该平台可用的最强质量档，不能仅用版本数字猜。用户已明确指定则优先遵从。
3. 能显式设置 model/size/quality 才传入；入口由平台自动路由且不披露型号时，记录原生入口与“不披露底层型号”。不能声称手动选中了 Image2.5、Imagen 等名称。
4. 记录核验日期、文档/工具说明、可用字段、原生生成与参考编辑能力、已知尺寸约束和未知项。官方 API 文档不能证明当前 Agent 原生入口拥有同一参数或上限。
5. 把建议比例和清晰度写进有效参数或提示词；生成后读取实际像素/比例。实际能力不够就报告具体限制，并给能实现的选择。

## Codex 可用 image_gen 时

优先内置 image_gen；无需 API key。当前工具说明为准，不照抄其他版本接口。新图生成与图片编辑区分清楚：新作可用授权风格参考；编辑先查看目标原图，再传入目标及支持素材并声明各自角色。

存在 referenced_image_paths 时可用已知本地参考路径；无本地路径则按工具说明用最小必要的近期图像上下文。不得同时传入互斥参考机制。逐张生成；先验收第 1 张，再引用其作第 2 张的风格锚点。

原生入口如果只接受 prompt 与参考，没有 model/size 参数，就不能杜撰参数。可在 prompt 中请求超长和高清，之后对实际文件验收；不能仅凭请求文本声明达到了设定比例。

## 极限长图与替代路线

选满足文字和可读性的尺寸，不默认所有图都用最大长度。当前原生上限不足时：保留文案、规定页数和断点，明确卡在哪个边长/比例/像素/接口能力，再请用户选择可行路线。不得自行缩字删字、加页、用 HTML/SVG/Python 排海报、改走付费 API 或分段拼接。

若用户明确授权其他路线，可用原生分段生成/扩图及获准的机械拼接等完成约定的一张或两张；需复核接缝、材质、字号、上下文连续性和全图真实尺寸。未经授权不把这条路线当默认。

API 与 CLI 只在用户明确选定后使用，并遵循相应官方 Skill/工具要求。不要让客户为原生能力配置不必要的密钥。某平台没有原生生图就说明缺口，不宣传该平台已能直接生成。
