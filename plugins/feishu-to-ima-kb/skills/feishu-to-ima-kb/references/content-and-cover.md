# 手册、描述与封面

## 根目录手册

文件 `manual.md` 使用 UTF-8，首行固定 `# 先看这里｜ima 知识库实操手册`。正文要短而能跟做，可采用以下骨架并填入真实内容，禁止把占位符上传：

1. 这套库解决什么：来自真实首页的一句话，附适合人群。
2. 第一次从哪里开始：按真实模块给 2—4 步学习路径，有基础的人如何直接查问题。
3. 怎么打开资料：点击文件夹内的原飞书链接；需要飞书访问权限时按原资源要求登录。原链接权限与 ima 成员权限分别管理，加入 ima 不会自动获得飞书权限。
4. 怎么向 ima 提问：使用与真实内容有关的两个具体问题。若网页实际未解析全文，明确先打开原资料，并粘贴已授权的必要内容再提问；不能承诺 ima 已学习私有飞书全文。
5. 怎么实践：选当前业务问题→读相应资料→照做一次→记录结果与卡点→再问具体问题。
6. 使用边界与求助：成员可查看、不可导出（只有真实核验后才写“已设”）；源资料的访问与求助采用客户自己的信息。

保留原首页中仍有效的资源入口和必需提示，删去只适用于飞书目录操作的说明。没有资料依据的课程、价格、收益、权益、更新频率不得添加。

## 描述

一行，优先“帮谁＋围绕什么＋怎样使用/得到什么能力”，需要联系方式时接客户自己的微信或其他入口。身份与联系方式从任务或当前源中明确识别，缺失只问必要一项。不要把开发者名、微信写入客户库。先检查当前 API 的长度限制；超限压缩表达，不能省略客户已要求的联系方式。

## 品牌封面

调用当前真实生图能力，结合资料主题和客户品牌；优先简洁醒目的知识库标题和能解释主题的图形，文字少、层级清楚、缩小后仍可读。长期封面不自动加日期、销量、收益或限时活动。客户未授权人物/IP 形象时不植入开发者的角色资产。

内置 V1 上传适配器接受原始 PNG，文件名 `知识库封面.png`，小于 3 MiB；建议在生成时就满足，保持原始二进制。这个大小是适配器的保守限制，不宣称是 ima 的统一平台上限。不同格式须使用当前官方支持且已验证的上传路线，不能把扩展名改成 png 或静默压缩绕过预检。

先用图像查看工具检查实际生成图，再上传与设置。随后读取知识库真实 cover_url，下载其真实缩略图到 `evidence/cover-actual.png` 并再次用图像查看工具打开。检查：标题无错字、无乱码，中心裁切不遮关键信息，色彩清晰，画面无变形。记录实际观察、工具引用、时间和图像哈希；图片存在、尺寸合格和上传成功都不等于视觉通过。

如果生图失败或不可用，保存当前进度并说明所缺能力，不能以占位图、文字描述或脚本校验代替封面成品。
