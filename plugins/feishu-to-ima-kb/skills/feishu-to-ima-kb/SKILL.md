# 飞书一键转 ima 知识库 · V1

把已做好的飞书知识库，变成客户打开就知道怎么学、怎么用的 ima 知识库。客户的资料、品牌、联系方式决定产物。执行前读 [流程与节点契约](references/workflow.md)，按节点保存输入、选择、产物、证据、通过条件和失败接续，不能用一段长提示词替代实际调用。

首次使用给出简短欢迎和开发者署名：`@半目 版权所属 / ➕微信 banmu23 / 获取持续更新🧡`。这行只属于 Skill 欢迎与说明，不能自动写入客户的知识库、描述或封面。

## 版本与维护

新会话首次调用时按 [版本检查与更新](references/update-policy.md) 读取统一发行源的公开版本；失败不阻塞当前任务。发现新版先展示变化，客户确认后再替换安装，不静默升级或发布客户资料。

## 固定交付与边界

- 来源首页改写为简短的 ima 实操手册，关联根目录，置顶后回读确认第一个入口。
- 原二级模块标题原样作为 ima 一级文件夹；原三级资料的原始飞书 URL 直接导入相应文件夹。保留大小写、路径、查询参数、片段，不缩短、不改写、不用 AI 摘要代替原链接。
- 提炼有事实依据的一句话描述，附客户确认或源中明确的联系方式；缺失时只问这一项，不能套用开发者微信。
- 根据客户内容和品牌真实生成封面，上传并设置；必须打开实际在线缩略图检查清晰度、裁切和文字。
- 成员权限必须达到【内容可查看，但不可导出】。HTTP 成功、`code=0`、请求字段、创建者账号可访问，都不能单独证明权限生效。
- 只通过已连接 API/连接器操作 ima。没有权限读写能力时，保留待验收并给客户一个必要手动动作；禁止改用电脑控制或屏幕共享绕过。
- 不修改来源飞书库；不自动删除资源、覆盖人工修改、公开发布、外发消息或安装依赖。

## A—C：读取和确定映射

1. 复用用户已经给出的来源、授权和选择，检查当前连接的真实只读结果。缺连接时按 [来源与映射](references/source-and-mapping.md) 引导当前一个必要动作；密钥不进聊天、日志或交付包。
2. 分页读完指定首页下的目录，保存首页最新正文、节点、原 URL、原顺序、版本及哈希。禁止搜其他客户的库，禁止把列表上限当作全量。
3. 在空白、同名模块、更深层级、重复 URL、正文内链接集合、同名目标等真实分歧上给少量可比较选项。正常结构直接沿用固定映射，不让客户重复批准每一个普通技术步骤。
4. 默认可用 Python 3.9+ 和现有 lark-cli 运行 `scripts/scan_feishu.py`；也可使用已连接的同等读取工具，输出相同完整来源契约。运行目录属于客户私人工作区，不放在 Skill 安装目录。

## D：准备可审阅内容

按 [手册、描述和封面](references/content-and-cover.md) 写 `manual.md`、`description.txt` 并调用当前可用的生图工具生成原始 `知识库封面.png`。读真实来源，不编造收益、课程、权益和案例。手册必须解释学习路线、原链接怎么打开、如何提问、权限边界和求助方式。飞书私有页是否被 ima 解析须实际检查；导入成功不等于 AI 能读全文。

先检查本地成品，再线上写入。客户已有品牌和风格直接沿用；只在关键风格确实不明且会影响成品时询问。生图能力缺失则保存断点，不能拿空白占位图冒充生成。

## E—G：执行、回读与视觉验收

按 [已验证 API 机制](references/ima-api.md) 执行。内置脚本覆盖标准结构新建，以及同一运行记录绑定目标的接续；任意既有库合并需要先读取、计算差异和明确映射，禁止按名称自动认领。

```bash
python3 <skill>/scripts/scan_feishu.py --source '<飞书首页原链接>' --out '<私人目录>/source.json'
python3 <skill>/scripts/migrate.py plan --source '<私人目录>/source.json' --run-dir '<新运行目录>'
python3 <skill>/scripts/migrate.py authorize --run-dir '<运行目录>' --user-request '<用户已给出的真实任务授权>'
# Agent 准备 manual.md、description.txt 和真实生成的 知识库封面.png 后执行
python3 <skill>/scripts/migrate.py run --run-dir '<运行目录>'
```

尖括号是 Agent 需替换的实际值，不把这些命令推给新手运行。`authorize` 只记录已有真实授权，不要求客户再点一次确认。脚本权限适配器未提供写入方法；运行后待权限或视觉证据属于预期状态，不能改报成功。

逐条核对导入后的原 URL、父文件夹、数量和手册内容；读取根目录顺序；打开 `evidence/cover-actual.png` 目视实际缩略图。使用 [证据与接续](references/evidence-and-resume.md) 记录与当前缩略图哈希绑定的真实观察。任何人工修改、同名冲突或不确定写入先停在对应节点，禁止清库重跑。

## H：权限是独立完成关卡

先查当前连接是否有经过核实的权限字段语义与真实读回。具备能力时，通过连接器按当前契约设置，再读取实际配置或普通成员结果，记录目标标识和原始证据。

如果缺少真实权限读写链路，明确告诉客户：【库的内容已处理到当前进度；权限尚未验收。请在 ima 的本库管理/权限设置中，将成员设为内容可查看、不可导出并保存，再告诉我实际结果。】界面名称随当前版本核实，不编造按钮位置。

只有收到客户明确说明实际已设置的回复，才记录为 `user_manual_confirmation`；不得由 Agent 代填确认。客户手动完成必须标注完成者为客户，不能宣称全自动。接口确认回执、猜测枚举和权限缺省值一律不能通过此关。

## I—J：最终验收与交付

重新只读扫描同一飞书来源保存新快照，使用 `check-source --snapshot <新快照> --run-dir <运行目录>` 比对；源发生变化先回到映射节点。随后运行 `verify --run-dir <运行目录>`，全部必需项通过才交付完成。

交付实际可打开的 ima 入口、模块与链接数量、手册与封面情况、权限实际结果和完成者。缺项就报当前状态、唯一缺口及恢复入口。脚本退出 2 表示需处理/接续，退出 3 表示必需项尚未验收；两者都不能当完成。跨平台能力说明见 [调用提示词与支持边界](references/cross-platform-prompts.md)。

## 质量优先的 Token 节省

成品质量、事实准确、隐私安全和业务判断优先。先用索引定位最小必要材料，长源分页分批读取，复用已确认选择与运行状态，不重复粘贴整库或索要授权。不能为省 Token 跳过完整目录、原 URL 核验、权限证据、实际封面目视和成品验收。平台或流程发生变化先改流程节点，再同步指令、引用、脚本、说明和安装包。
