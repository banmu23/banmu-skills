# 对标口播核心要点融合规范

## 硬规则

只要用户提供了对标口播逐字稿，或提供了针对对标逐字稿的详细分析，就必须真正使用。不能只做表面阅读、只学一句开头，或生成一篇与对标核心精华无关的稿件。

## 什么属于核心、关键要点

满足任一条件即可视为核心点：

- 决定整篇口播主命题或主要承诺
- 是观众继续听下去的核心钩子或冲突
- 是主体结构中不可缺少的一层
- 是关键方法、步骤、判断、案例、证据或反转
- 在对标分析中被用户明确标注为“核心、关键、必须参考”
- 被重复强调，或承担从问题到结论的必要逻辑
- 是独特且有效的画面、类比、节奏安排或 CTA 设计

## 覆盖矩阵

写稿前在内部建立：

| 对标核心点 | 类别 | 为什么重要 | 本稿融合位置 | 融合方式 | 状态 |
|---|---|---|---|---|---|
| 核心命题 / 步骤 / 案例等 | 钩子 / 结构 / 论证 / 证据 / 节奏 / CTA | 对逻辑或效果的作用 | 开头 / 主体 / 结尾 | 保留逻辑、改写表达、替换为本人案例等 | 已采用 / 未采用 |

对标分析已经列出关键点时，先把分析中的每一项放入矩阵；若同时有原逐字稿，再回到原文核对是否有遗漏或误读。

## 融合方式

1. **保留核心命题**：换成发布者自己的立场和语言。
2. **保留有效结构**：根据本次素材重排，不复制表面段落。
3. **保留论证功能**：用发布者自己的事实、案例和证据替换。
4. **保留画面机制**：使用发布者习惯的隐喻，不照抄对标独特措辞。
5. **保留节奏作用**：例如最后一个要点最强、案例后立刻下判断。
6. **保留 CTA 目的**：用发布者真实的互动或产品入口重新表达。

## 冲突处理

- 与事实冲突：不用对标事实，保留可迁移的逻辑。
- 与发布者风格冲突：保留核心内容，用发布者自己的气口、幽默和判断重写。
- 与主题目标冲突：标记未采用并说明原因，不悄悄忽略。
- 与隐私或平台规则冲突：删除风险信息，寻找安全替代。
- 对标本身信息较弱：如实降低权重，但仍检查用户明确要求参考的点。

## 禁止动作

- 移植对标作者的个人经历、客户案例、数据、身份和承诺
- 连续复刻具有辨识度的独特句式或长段表达
- 用对标作者口头禅覆盖发布者本人风格
- 只抽取标题和开头，遗漏主体核心方法
- 因为某个核心点难融合就直接跳过
- 把“综合参考”平均稀释，导致关键精华全部变淡

## 交稿前覆盖审计

逐项回答：

```text
对标的核心命题是否进入成稿？
关键结构和推进逻辑是否被利用？
重要步骤、判断、案例功能是否被承接？
最有效的画面和节奏是否做了适配？
CTA 的作用是否得到保留或合理替换？
是否仍然像发布者本人，而不是像对标作者？
有没有未采用的核心点？原因是否成立？
```

存在无理由遗漏时，必须重写。用户要求只看逐字稿时不展示矩阵，但覆盖审计仍是硬步骤。
