# 口播结构选择

## 1. 教程演示型

```text
结果 / 能做成什么
→ 旧痛点或为什么值得学
→ 按顺序演示 2-5 个动作
→ 补关键避坑或效果证明
→ 总结适合谁、下一步怎么做
```

重点：一句一个动作，每一步都有可见结果。不要先讲大段工具背景。

## 2. 认知判断型

```text
真实困惑 / 冲突 / 反常识判断
→ 解释问题为什么发生
→ 给 2-4 层判断或路径
→ 用本人经历、案例或类比支撑
→ 给一个可以马上执行的动作
→ 自然互动或收住
```

重点：判断必须有事实或场景支撑，不把一个锋利观点稀释成正确作文。

## 3. 案例故事型

```text
先给结果或最有冲突的节点
→ 人物、起点和真实卡点
→ 关键动作与转折
→ 结果和证据
→ 这件事说明什么
→ 对观众有什么可复制动作
```

重点：保留不顺、犹豫、失败和现场细节；不要写成成功学，也不要编造戏剧冲突。

## 4. 产品服务解释型

```text
用户正在经历的具体麻烦
→ 为什么常规做法解决不了
→ 产品 / 服务到底帮他完成什么
→ 使用过程或交付方式
→ 真实边界、适合谁、不适合谁
→ 自然行动入口
```

重点：把功能翻译成使用画面和业务结果，不把口播写成权益清单或销售页。

## 融合结构

一个主题可以融合两类，但必须只有一条主线。例如：

- 案例故事为主，结尾拆出认知判断
- 教程演示为主，开头用真实案例证明结果
- 认知判断为主，结尾自然承接产品服务

不要把四类结构平均拼接。先确定观众看完最该记住的一件事，再决定其他内容是否服务这条主线。

## 时长与密度

- 30-60 秒：一个钩子、一个核心点、一个动作
- 60-90 秒：一个问题、2-3 个推进块、一个收口
- 2-3 分钟：允许案例、完整解释和分层方法，但每 20-30 秒应出现新信息或推进
- 未指定时长：以讲清楚一件事为准，能短则短，不为完播率牺牲必要事实
