# 一键生成口播逐字稿

## 目标

把主题、知识库和真实素材写成一份“张嘴就能录”的口播逐字稿。优先还原发布者自己的说话方式、判断和业务现场；客户使用时，切换为客户自己的知识库和表达风格。

## 硬优先级

按以下顺序处理冲突：

1. 事实准确、隐私安全、平台合规
2. 用户本轮明确要求和最新可靠资料
3. 发布者真实口吻、已发布终稿和稳定判断
4. 对标素材中必须参考的核心、关键要点
5. 可说、顺口、能录、能听懂
6. 模板完整度和文字漂亮程度

不得为了模仿对标而改写事实，不得为了像某种风格而编造经历、案例、数据、效果、身份或产品承诺。

## Quality First Token Efficiency（质量优先的 Token 节省）

- 先判断任务目标、输出形态和最小必要资料源，不无差别读取整库。
- 长材料、历史逐字稿和对标素材按主题分批提炼；但不得跳过关键事实、关键风格样本或对标核心要点。
- 能从知识库识别的变量不重复询问，只补问会实质改变成品的缺口。
- 默认先给成品，少写无用过程说明；需要教学、复盘或交付说明时再展开。
- 按需读取 `references/`，复用既有风格画像、终稿规则和上一轮确认。
- Token 节省与成品质量冲突时，成品质量优先。

## Workbench Sync Loop（工作台同步闭环）

当用户提供最终口播稿、真实发布反馈、对标融合修正、风格校准意见、产品资料变化或客户使用反馈时，判断它是一次性偏好还是稳定规则。

稳定规则应同步评估是否更新 `SKILL.md`、`references/`、脚本、使用说明、客户知识库模板、跨平台调用提示词、产品服务卡和一键上传 ZIP。涉及价格、权益、公开承诺、客户隐私、未确认数据或新命名时，只列为待确认项。

## 资料读取

按任务需要读取：

- 发布者说明、定位、受众、产品与禁区
- 历史口播逐字稿、真实录音转写、已发布终稿和改稿对照
- 当前主题的原始素材、案例、数据、截图说明和产品资料
- 客户需求、目标受众原话和高频卡点
- 对标口播逐字稿、对标视频转写或针对对标的详细分析
- 相关方法论、内容模板和平台约束

资料较多或目录不清楚时，先读 [knowledge-sources.md](references/knowledge-sources.md)。同一内容有多个版本时，默认采用时间最新、状态最明确的终稿，旧稿只用于观察演化。

## 工作流

### 1. 判断任务和最小变量

从上下文识别主题、目的、受众、平台、口播类型、时长、真实事实、风格资料、对标素材、CTA 和交付格式。

资料足够时直接生成。只有缺失内容会导致事实失真、结构方向错误或重大返工时，才询问 1-3 个最必要问题。

### 2. 提炼发布者口吻

有历史内容时，必须先提炼口吻，再写稿。读取 [style-extraction.md](references/style-extraction.md)，至少识别：身份关系、开头习惯、句子气口、自然转场、判断强度、举例方式、幽默尺度、画面隐喻、教学方式和 CTA。

历史文本很多时，可运行：

```text
python scripts/profile_corpus.py <文件或目录> [更多文件或目录]
```

脚本只用于统计辅助，不能替代对真实内容的语义判断。

### 3. 强制处理对标素材

只要提供了对标口播逐字稿，或提供了针对对标逐字稿的详细分析，就必须读取 [benchmark-integration.md](references/benchmark-integration.md)，并完成以下动作：

1. 提取对标的核心命题、关键结论、钩子、结构、论证、案例、步骤、画面、节奏和 CTA。
2. 标记哪些属于“必须参考”，不能只挑容易写的部分。
3. 把核心要点与发布者知识库、真实事实、本人风格和本轮目标综合融合。
4. 保留对标的有效逻辑和信息价值，用发布者自己的口吻重新组织，不照抄独特句式。
5. 交稿前做覆盖审计；未采用的核心点必须有事实、隐私、平台、主题或风格冲突方面的明确理由。

不能出现“看过对标，但成稿与对标核心精华几乎无关”的情况。

### 4. 选择口播结构

读取 [script-structures.md](references/script-structures.md)，选择或融合教程演示型、认知判断型、案例故事型或产品服务解释型。

模板只提供逻辑骨架。素材的自然理解顺序与模板冲突时，服从真实素材的逻辑链。

### 5. 先搭口头提纲

先在内部确定：一句话核心承诺、开头钩子、观众继续听的理由、主体 2-5 个推进块、关键案例或证据、最后动作和自然收口。

不要机械展示提纲，除非用户要求先看结构。

### 6. 写成能录的逐字稿

- 开头尽快给痛点、结果、冲突或反常识判断，不写空泛背景。
- 先说人话，再讲方法；技术词必须翻译成观众能理解的场景和结果。
- 短句负责抓人，中长句负责讲透；以一口气能自然说完为准，不机械碎句。
- 使用自然转场和口语停顿，但不堆填充词。
- 每个内容块至少有一个具体动作、场景、案例、数字、画面、对比或判断。
- 保持推进感，后一段要回答前一段刚产生的问题。
- 允许鲜明判断、自嘲、轻幽默和画面隐喻，但必须符合发布者真实风格。
- 不把公众号文章换行后冒充口播，不写播音腔、论文腔或短视频鸡血腔。
- 镜头、截图或演示提示使用简短的 `[画面：...]`，只在确实有帮助时加入。

未给时长时，以讲清楚一件事为准。给出时长时，按发布者真实语速估算；没有历史语速时，可将每分钟约 250-320 个中文字符作为粗略起点，随后以朗读效果修正，不为凑时长注水。

### 7. 做事实与风险检查

- 核对人名、身份、时间、数据、案例、产品、价格、权益和效果承诺。
- 对标中的人物、品牌、数据和案例不能自动移植给发布者。
- 不确定信息使用 `【需确认】`，不要补写成确定事实。
- 涉及客户、学员、付款、私聊、截图或未发布资料时，默认检查隐私和公开边界。
- 不自动发布，不自动删除、归档或改动用户素材。

### 8. 朗读和覆盖审计

交稿前读取 [recordability-rubric.md](references/recordability-rubric.md)，至少完成：

1. 逐句默读或模拟朗读，修掉拗口、过长、书面和歧义句。
2. 检查开头是否在前几句建立继续听的理由。
3. 检查整篇是否有具体内容和自然推进。
4. 检查是否像发布者本人，而不是像模板或对标作者。
5. 有对标素材时，逐项核对核心要点覆盖情况。

任何事实、本人风格、对标核心覆盖或可录性硬门槛不通过，都必须重写后再交付。

## 默认输出

直接输出成品：

```text
口播逐字稿
【可直接录制的正文】

镜头 / 画面提示
【仅在确实需要时输出】

对标融合说明
【仅在提供了对标逐字稿或详细分析时输出：已吸收的核心点；未采用项及原因】

发前确认
【仅在存在待核实事实、隐私或平台风险时输出】
```

如果用户明确要求“只给逐字稿”，只展示逐字稿；对标覆盖审计仍需在内部完成。

## 修改指令

- “更像我”：重新读取历史终稿，重点调整开头、气口、转场、判断、幽默、隐喻和 CTA，不是只替换口头禅。
- “再短一点”：重抓核心承诺、关键论证和行动入口，不做机械删句。
- “更有网感”：增强冲突、具体画面和继续听的理由，不制造虚假夸张。
- “更顺口”：优先修气口、长句、书面词和内容块承接。
- “对标参考得不够”：重新打开对标覆盖矩阵，补回遗漏的核心、关键要点，再用本人风格重写。
