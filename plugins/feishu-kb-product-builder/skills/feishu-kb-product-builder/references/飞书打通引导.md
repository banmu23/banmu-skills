# 飞书打通引导

当用户没有打通飞书，先把用户当成纯新手带着做，不要直接开始写“请复制到飞书”。

## 1. 先判断当前可用方式

按顺序确认：

1. 当前 Agent 是否有飞书 / Lark 文档能力。
2. 是否能读取用户提供的 Feishu docx / wiki 链接。
3. 是否能创建、编辑、移动 Feishu 文档。
4. 是否能上传和插入图片。
5. 是否有权限访问目标知识库。

如果工具可用，先做一个无破坏测试：读取一个文档标题或创建一个测试草稿，而不是直接清空或批量写入。

## 2. 如果用户使用 lark-cli

引导用户确认：

```text
lark-cli 是否已安装
是否已登录
docs / wiki / drive 权限是否可用
目标知识库链接或空间 ID 是否提供
```

实际执行中优先使用相对路径上传本地内容和图片，避免 CLI 对绝对路径不兼容。

涉及删除、清空、移动、批量创建节点，必须先展示计划并等用户确认。

## 3. 如果用户没有飞书 API 或 CLI

提供“手动可落地模式”：

1. 先生成完整知识库结构。
2. 每次只输出一个文档的正文。
3. 给出图片插入位置和说明。
4. 让用户手动复制到飞书。
5. 等用户反馈截图或链接后，再继续下一篇。

不要因为无法自动写入飞书就停止。先把内容产品做出来。

## 4. 新手打通路径

给新手的引导要分小步：

```text
第一步：确认你要写入哪个飞书知识库
第二步：确认你的 Agent 能不能读取飞书链接
第三步：确认能不能创建一个测试文档
第四步：确认能不能上传一张测试图片
第五步：再开始正式搭建结构
```

每一步只让用户做一个动作，等确认后再进入下一步。

## 5. 风险边界

- 不在未确认时清空知识库。
- 不在未确认时删除节点。
- 不在未确认时批量移动文档。
- 不把 API 错误、block_id、local_id、占位符写进客户可见文档。
- 如果权限不足，说明缺哪个权限，给用户下一步授权动作。
