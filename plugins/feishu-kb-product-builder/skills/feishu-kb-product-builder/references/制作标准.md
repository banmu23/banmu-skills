# 飞书知识库产品制作标准

## 1. 核心原则

飞书知识库产品不是资料搬运，也不是课程摘要。它要把真实课程、文档、案例、答疑、图片和工作流，整理成客户愿意阅读、能够跟做、可以复用、方便迭代的产品。

执行时遵守：

- 先读真实素材，再写结构和正文。
- 只围绕用户指定素材写，不跨源发挥。
- 对未完结课程，可以按真实目录和已知课程逻辑规划空框架，但不要编造未交付正文。
- 不写“待更新、预留、版本记录、群聊高频问题、作业打卡、小作业、风控”等内部或幕后表达。
- 平台安全要求是写作约束，不写进知识库正文，除非用户明确要求做合规章节。
- 标题、小节标题、模块标题都要面向客户，一眼看到能知道解决什么卡点。

## 2. 先确认方案再执行

正式写入、删除、清空、创建目录、生成图片、调用飞书接口、批量插图前，先给用户确认方案。

标准互动顺序：

1. 复述当前任务目标和素材边界。
2. 给出知识库标题、目录结构、页面类型、执行顺序。
3. 标明会不会清空已有内容、会不会写入飞书、会不会生成图片。
4. 等用户确认。
5. 用户不满意时继续改方案，直到确认。
6. 确认后再执行具体动作。

这条规则用于减少返工和无效 token 消耗，但不能为了省 token 牺牲事实核验、素材阅读、图片审计和成品质量。

## 3. 固定页面层级

默认层级必须固定为：

```text
一级目录：只有首页 / 知识库总览模块文档
  二级目录：各模块文档
    三级目录：各模块下的小节正文文档
```

标准树形示例：

```text
首页｜知识库总览
  01 模块文档
    1.1 小节正文文档
    1.2 小节正文文档
  02 模块文档
    2.1 小节正文文档
    2.2 小节正文文档
```

执行要求：

- 一级目录只保留首页 / 知识库总览文档。
- 二级目录才是模块文档。
- 三级目录才是各模块下的小节正文文档。
- 不要把模块文档和首页并列到一级。
- 不要在首页下堆很多快捷方式索引。
- 不要创建“待更新、预留、版本记录、群聊、作业、打卡、后台索引”等客户不需要看的页面。
- 如果课程后续未完结，可以先把二级模块和三级小节框架搭好，未写正文的小节保持为空或仅保留标题，不编造内容。

## 4. 首页写法

首页是一级目录，也是全局入口。它像“产品开篇 + 全局导航”，不是长篇课程正文。

首页重点让客户快速判断：

- 这套知识库带我做什么
- 适合谁
- 我能从哪里开始
- 全局结构是什么
- 后续怎么跟着走

首页不要写成长课文。优先使用：

- 开篇判断
- 适合人群表格
- “这套知识库带你做什么 / 不做什么”对比表格
- 全局目录导航
- 简短使用路径

首页要随着后续正文填充持续迭代。

首页建议结构：

```text
一句话开篇判断
这套知识库带你完成什么
这套知识库适合谁（表格）
这套知识库带你做什么 / 不做什么（表格）
全局目录导航（嵌入子页面导航或清晰模块列表）
怎么使用这套知识库
当前建议从哪里开始
```

首页控制原则：

- 精炼，不写成详细教程。
- 多用表格承接“适合谁”“做什么/不做什么”。
- 必须嵌入知识库全局目录导航。
- 后续每填充完重要模块，要同步检查首页是否需要迭代。

## 5. 模块页写法

模块页是二级目录文档，作用是提纲挈领、承上启下、帮用户进入本模块，不是正文长文。

模块页必须：

- 快速说清本模块解决什么问题
- 提炼本模块下每个子文档的重点
- 嵌入 Feishu 子页面导航
- 让客户知道先看哪一节、每一节能带来什么

模块页不宜过长。它的目标是“抓重点、给路径、带进入”。

模块页建议结构：

```text
本模块先解决什么卡点
学完本模块你会得到什么
本模块目录导航（必须嵌入 Feishu 子页面导航）
子文档提炼表：小节标题 / 解决的核心问题 / 跟做后的产出
本模块建议学习顺序
完成本模块后的验收结果
```

模块页写法细节：

- 控制在“清楚但不啰嗦”的长度。
- 小节提炼要像客户看得懂的产品卖点，不写幕后管理语言。
- 不提前把每个三级正文的全部步骤写进模块页。
- 如果模块下小节还没写正文，模块页可先保留小节提炼，但不要写“待更新、预留、空白”等字样。
- 模块页文案确认后，必须主动调用 `feishu-doc-beautifier` / 飞书美化文档 Skill / 等价美化能力；美化后必须主动调用专属视觉 IP或客户视觉 IP 配图 Skill。

## 6. 正文文档写法

正文文档是三级目录文档，必须详细、实操、落地，让完全新手也能跟着一步步完成。

默认结构：

```text
作者块
本节先解决什么问题
核心判断
路线拆解
操作步骤
可复制口令 / Agent 指令
新手容易卡在哪里
验收标准
下一步去哪里
```

正文要求：

- 新手看完知道第一步点哪里、把什么资料交给 Agent、Agent 会产出什么、自己要确认什么、怎么判断结果是否可用。
- 不要把 Agent 应该做的诊断、整理、归类、生成工作丢给客户手填。
- 如果需要客户参与，客户只负责确认、补充事实、选择方案、修正不准确处。
- 不把后续章节的内容提前写满。当前文档只写当前主题，必要时指向后续章节。
- 每个核心动作都要写成可以照做的步骤，不只讲概念。
- 给出可复制的 Agent 指令 / 口令，并说明输入什么、输出什么、如何验收。
- 能用原课件图、真实截图、流程图解释的地方，优先插入源图。
- 写完文案后必须暂停，让用户审核确认；确认后再美化和配图。

三级正文默认使用可配置作者块：

```text
✔️原创作者：{author_name}丨{contact_or_brand}
```

客户通用包必须把作者块做成可配置项。

正文详细度标准：

```text
普通说明：不合格
能让读者理解：只算及格
能让读者复制口令、提交素材、检查结果、进入下一步：合格
能让纯新手少走弯路、知道卡住时怎么改：优秀
```

正文中不要写“你自己填写个人说明书、自己整理素材表、自己复盘记录”这类把 Agent 工作甩给客户的表达。正确写法是：

```text
把资料交给 Agent 做第一轮扫描
让 Agent 先生成结构化草稿
你只负责确认：准不准、漏没漏、哪些不能写
确认后再让 Agent 保存、改写、归类或进入下一步
```

## 7. 每篇文档的固定生产流程

除非用户另有要求，每篇文档都按这个顺序：

```text
1. 深度阅读本篇对应的真实素材
2. 先列本篇文档的写作范围，不抢后续章节内容
3. 撰写文案草稿
4. 发给用户审核确认
5. 用户确认后，必须主动调用 `feishu-doc-beautifier` / 飞书美化文档 Skill / 等价美化能力
6. 美化后，插入本篇用得上的源课程图片 / 原飞书图片
7. 再必须主动调用专属视觉 IP或客户视觉 IP 配图 Skill
8. 检查图片比例、白边、压缩、位置、标题、说明
9. 最后告诉用户本篇已完成，下一篇应该写哪一篇
```

关键顺序不能反：

- 不能文案没确认就配图。
- 不能没美化就直接插专属视觉 IP图。
- 不能只生成小黑图，忘记源课件图。
- 不能每篇机械固定两张图。
- 不能把模块页写成正文，也不能把正文写成模块页。
- 不能因为没有安装美化 Skill 就完全跳过美化；必须手动做到最优。
- 不能因为客户没有小黑 Skill 就跳过配图；必须引导客户安装、创建或改造客户自己的视觉 IP Skill。

## 8. 知识库整体铺排

客户-facing 内容要做到：

- 结果前置
- 问题前置
- 直接判断
- 少讲概念，多给动作
- 像真人老师带着做，不像 AI 说明书
- 把工具翻译成业务价值
- 避免夸张承诺、绝对化结果、收益保证

推荐句式：

```text
这一节先帮你省掉最容易浪费时间的一步：...
你不是缺工具，而是缺一个能跑通的顺序。
这一步不要急着自己整理，先让 Agent 帮你做第一轮诊断。
你只需要确认三件事：准不准、漏没漏、能不能直接进入下一步。
```

整体铺排要求：

- 当前小节只写当前小节要解决的问题。
- 后续章节的内容只做自然指向，不提前讲完。
- 首页和模块页负责导航，正文负责实操。
- 未完结课程可以先搭结构，正文等源课程真实更新后再写。
- 每写完一篇正文，都回头判断首页和对应模块页是否需要微调。

## 9. 飞书美化规则

先确认文案，再美化文档，再配图。

美化时优先使用：

- 信息栏 / callout
- 表格
- 检查清单
- 分隔线
- 子页面导航
- 清晰的小标题
- 适度加粗
- 留白

“这套知识库适合谁”“这套知识库带你做什么 / 不做什么”“工具选择”“步骤判断”等内容，优先考虑用表格表达。

飞书美化必须主动调用已有 `feishu-doc-beautifier` / 飞书美化 Skill 或对应能力。

### 文档内标题层级与客户负担

- 标题层级由内容关系决定，不机械套模板。较长课程、指南、SOP、方案和交付文档通常收束为 3～7 个并列一级模块，再按真实需要展开二级或三级；短页面可以只保留一到两级。
- 一级标题承接主阶段或主模块，二级标题承接同一模块下的并列子主题，三级标题只用于确有多组独立步骤、方法或问题的二级主题。
- 同级标题必须并列，不能把阶段、动作、结果、提醒混成同一层级。使用飞书自动编号时，不在标题正文重复写 `1 / 1.1 / 1.1.1`。
- 面向客户或学员的实操内容，只保留首版跑通真正需要的动作、检查项和提醒项；明确区分必做与可选，避免“至少完成 X 项”“全部都要准备”等无效负担。
- 修改已有飞书文档时，以在线最新版本为准，保留人工修改，优先局部 block 或文字调整，不擅自移动文档目录或知识库节点。

如果已安装，直接调用，不要只在文字里建议。

如果没有该能力，按以下手动标准输出，并说明这是“当前环境下的手动最优美化方案”：

- 首页和模块页：表格、信息栏、子页面导航、清晰分区。
- 正文页：步骤编号、口令块、检查清单、注意事项、验收标准。
- 不要过度花哨，保持清晰、留白、层次。

## 10. 原课件配图规则

当用户给出原飞书课件或课程素材：

1. 先统计源文档图片总数。
2. 判断每张图是否可复用。
3. 所有可用原图都直接插入新知识库文档的对应位置。
4. 保持原图清晰度和比例，不拉伸、不压扁、不做截图拼接。
5. 如果图片下载或权限受限，说明原因，并请用户授权或提供本地原图。

源图用于承接证据、界面、流程、课件原意。生成图用于解释结构、缓解理解卡点、增强阅读体验。两者职责不要混淆。

## 11. 专属视觉 IP / 视觉 IP 配图规则

视觉 IP 图必须在文案确认和飞书美化后再做。

数量由内容决定：

- 短模块页：可 1 张或不配，视内容而定。
- 长正文：按关键判断、实操动作、易卡点、闭环节点配置多张。
- 不固定每篇两张，不用装饰图凑数。

专属视觉 IP风格内部默认：

- 16:9 PNG
- 纯白背景
- 手绘正文插图
- 表情可爱、阳光、有趣、丰富
- 不苦、不中年疲惫脸、不固定苦逼表情
- 少量红橙蓝中文批注
- 不做 SVG、HTML、Canvas、PPT 拼图

插入飞书后必须检查尺寸，避免 512x512 正方形导致下方大片白边，或图片被压缩变形。常用宽高可用 760x428；源图按原比例设置。

如果任务是内部知识库，必须严格调用 `customer-visual-ip-illustrations` / 客户自己的视觉 IP 配图 Skill / 能力。

如果是客户使用，必须调用客户自己的小黑 / 视觉 IP 配图 Skill。客户没有安装时，要先引导客户一步步安装、创建或改造客户自己的视觉 IP Skill，不要擅自用专属视觉 IP替代客户形象，也不要直接跳过配图。

专属视觉 IP配图不是每篇固定两张，而是按内容适配：

```text
模块页：通常 1 张，除非内容很短可以不配
短正文：1-2 张，放在关键判断或卡点处
长正文：按步骤、卡点、闭环节点配置多张
答疑/案例精华：至少在关键判断或流程总结处配 1 张
```

## 12. Feishu 图片验收

每篇文档插图后检查：

- 图片数量是否符合内容需要
- 源图是否完整复用
- 视觉 IP 图是否放在理解断点
- 宽高是否正确
- 是否有“白色下巴”
- 是否被压扁、拉伸、模糊
- 标题和图片是否语义匹配
- 图片说明是否自然，不泄露内部处理信息

发现图片不合格时，必须修正后再交付，不能用“已经插了图”糊弄。

## 13. 最终 QA

交付前检查：

- 结构层级正确
- 首页在最前
- 模块页不是正文长文
- 正文足够实操
- 作者块按场景正确
- 没有内部管理表达
- 没有编造结果、收益、价格、案例
- 没有敏感违规营销词
- 原图复用完整
- 视觉 IP 图数量合理
- Feishu 美化完成
- 客户可见包已脱敏、专属名词通用化
