# V2 最新自有视觉小黑 Skill 与充分配图

## 选择顺序

读取 runtime-profile.json。内部用已确认的内部角色家族最新版本；客户用客户生成、归属匹配、角色家族已确认的最新客户自有版本。候选登记真实路径、name、owner_id、family、版本和可用性，运行 resolve_visual_skill.py；不能按文件名猜拥有权，也不能只按修改时间选择。

版本优先读 VERSION，其次 SKILL.md metadata.version。支持 V1/V2/V3 和旧语义版本；先比较同家族版本，再用真实修改时间作同版本参考。版本并列但内容不同或归属不明时，只问必要选择，不自动选他人角色。安装存在不代表实际可用，必须读说明、参考并验证真实生成。

## 客户没有自己的：从 0 到 1

每次通常让客户完成 1–3 个必要动作；Agent 能做的安装、整理、改文件、打包与检查由 Agent 做。

1. 说明用途并检查环境：需要自有角色来解释知识库，不是装饰图。先识别当前平台可用的视觉小黑基础 Skill、真实生图工具、参考图支持和 PNG 输出；未知工具不默认安装。
2. 引导安装基础能力：读取客户允许使用的基础包、来源、说明与许可，说明要装什么、放哪里及需要何种权限；在授权内实际安装并核对资源，不能只发一句“去安装”。没有安全可用基础包时说明具体缺口，让客户选择已持有包或允许的来源。
3. 魔改成客户自己的角色：让客户提供人物/品牌角色定位、少量授权参考图或描述、风格偏好与禁忌。Agent 整理脸部/发型/服装/体型、表情动作、色彩、画风、参考策略、尺寸、PNG 输出与 QA；不复制原作者的专属形象。
4. 先画客户视觉 Skill 的流程图：来源与参考 → 角色确认 → shot list → 生图 → 逐图 QA → 定向返修 → 交付；包含失败路径与完成条件，再映射为步骤。关键中英文名称及角色方案由客户确认；已有授权不重复问。
5. 封装并安装客户自有 Skill：SKILL.md、角色规范、参考资产、生成工作流和 QA 形成自包含包；记录客户 owner_id、family 与 V1 版本，保留基础来源许可。ZIP 根目录直接有 SKILL.md。
6. 实际生成测试图：传入正确参考，生成符合本篇内容的真实 PNG，逐图打开检查身份、中文、肢体、肤色、动作、比例、风格与阅读清晰度。失败返回对应角色/提示词/工具节点；不得用程序图伪装生图结果。
7. 试图合格后登记为客户的最新自有版本，回到知识库正文配图。安装或写好提示词不算通过；未通过就保存进度，不自行换通用插图、他人形象或零图交付。

## 充分配图的覆盖表

逐节登记：anchor、原文依据、是否关键理解点、由 original/generated/text 哪一路承担、原因、对应 image_id。复杂点可拆多图，每图一义。源图用于事实和真实操作，生成图用于结构、判断、卡点和闭环；两者配合，不机械重复。

每个必要理解点必须关联实际合格图片。正文至少一张自有 IP 生成图仅为底线，不是张数目标；重要步骤/转折/误区漏图就补。纯导航且无难点页才可说明不适用原因，不允许因工具缺失或省 Token 而零配图。

## 生成与飞书呈现验收

严格调用所选最新视觉 Skill；遵守其参考、身份与画风规则，默认真实 AI 输出 16:9 PNG。保存提示词、参考文件哈希、调用记录和每张图的目视结果。源图按原比例；生成图显示宽约 760px 且等比例，以实际效果为准。

插入后回读数量、位置和尺寸，再看实际页面：无错字、模糊、拉伸、512×512 方图或白下巴；图与上下文对应、角色稳定、没有伪证据。尺寸或哈希通过不替代目视。
